## 2. Working rules (follow these every time)

1. **No em dash or en dash anywhere** in site copy, code output or documents. Use commas, colons, "to" or "and" instead. The build fails if one appears in the output.
2. **Prices in digits, always:** "Rs. 600,000", never "6 lac" or "6 lakh". Use `toLocaleString('en-US')` formatting.
3. **Speed first** on mobile and desktop. Inline CSS, tiny deferred JS, AVIF/WebP responsive images, lazy loading, no heavy libraries. Never hide the hero (LCP) image behind an animation.
4. **Subtle animations only:** fade or slide on scroll, smooth hovers. Nothing flashy. Always honour `prefers-reduced-motion`.
5. **Full SEO on every page:** unique title (60 chars or less), unique description (160 chars or less), one `h1`, alt text, canonical, Open Graph, JSON-LD. The build warns on long titles or descriptions; the audit must say "No problems found".
6. **Plan before code for new pages or major new sections:** share the layout and approach, then wait for approval. Content updates the client supplies (names, prices, logos, text fixes) can be built directly.
7. **Never push without the user's go-ahead.** The user replies "push" when ready. Pushing deploys to the live domain. After pushing, confirm with `curl` that the live site shows the change.
8. **Only add or remove what the client names.** Never infer that a new item replaces an old one (this caused a mistake once with the Mera Ghar card). If unsure, ask.
9. **Keep placeholders marked** with `// PLACEHOLDER` in `_dev/src/data.mjs` until the client gives real data.
10. Content lives in `_dev/src/data.mjs`. Never hand edit the built HTML in the repository root; it is regenerated.
11. Commit built output together with source changes (the root is what Hostinger serves).
12. Reply style: short and plain. Say what changed, what was verified, and what is still needed from the client.

## 3. Set up a new laptop

### Install
- **Git**
- **Node.js 20 or newer** (built and tested on Node 20.20)
- **Python 3.11 or newer** with these packages:
  ```bash
  pip install "pillow>=11" numpy opencv-python pymupdf
  ```
  Pillow must have AVIF support. Check with `python -c "from PIL import features; print(features.check('avif'))"`, it must print `True`.
  Tested versions: Pillow 12.2, NumPy 2.2, OpenCV 4.10, PyMuPDF 1.28.
- **Google Chrome or Microsoft Edge** (only for `documents.mjs`, which prints the PDFs). On macOS or Linux, check the `BROWSERS` list at the top of `_dev/tools/documents.mjs` covers your browser path.
- Optional: **GitHub CLI** (`gh auth login`) or Git Credential Manager, so `git push` can authenticate.

### Clone and check
```bash
git clone https://github.com/onecinfinity/alwaheedgroup.git
cd alwaheedgroup
git config user.name "Abdul Rehman"
git config user.email "<your email>"
node _dev/tools/build.mjs
node _dev/tools/audit.mjs
git status
```
- The build should print `Built 13 pages` and the audit `No problems found`.
- After a build on a new day, only dates change: `sitemap.xml` (`lastmod`), the job posting dates in `careers/index.html` and the date in `privacy-policy/index.html` (all use the build date, in UTC). Anything else changing means the setup differs; investigate before committing.
- Line endings are normalised to LF by `.gitattributes`; binary files are marked binary.

### Preview locally
```bash
python -m http.server 8765
```
Open http://localhost:8765. In the Claude desktop app, `.claude/launch.json` defines the same server as `alwaheed-site` for the preview pane.

## 5. Commands (run from the repository root)

| Command | When | What it does |
| --- | --- | --- |
| `node _dev/tools/build.mjs` | after any change in `_dev/src` | builds all pages into the root, inlines minified CSS, writes hashed JS, prunes deleted pages, writes sitemap, robots, llms.txt, manifest, copies .htaccess, fails on any em or en dash, warns on long titles or descriptions |
| `node _dev/tools/audit.mjs` | after every build | one h1 per page, unique titles and descriptions, alt text, broken links and srcset files, JSON-LD parse, duplicate ids, dead anchors, aria references; prints page sizes |
| `python _dev/tools/images.py` | only when photos or logos change | regenerates every image and `images.json` (slow; a different Pillow version produces different bytes, so expect a large diff) |
| `node _dev/tools/documents.mjs` | when the UPG payment plan, contacts or downloads change | prints the UPG payment schedule (A4) and layout plan (A3) PDFs, re-saves the Khairunnisa PDF, makes preview thumbnails; stops if payment rows do not add up to the total |

To regenerate a single logo without rebuilding all images:
```bash
python -c "import sys; sys.path.insert(0, '_dev/tools'); import images; images.other_logos()"
```
(`images.gold_logos()` for the gold badge logos, `images.partner_logos()` for the KH and Al Ghaffar logos.)

Check for dashes anywhere (Git Bash):
```bash
LC_ALL=C.UTF-8 grep -rlP '[\x{2013}\x{2014}]' --include=*.html --include=*.txt --include=*.mjs --include=*.css --include=*.js --include=*.md .
```

### Standard change routine
1. Edit `_dev/src/...` (usually `data.mjs`).
2. If images or logos changed: run `images.py` (or the single logo function). If the payment plan changed: `documents.mjs`.
3. `node _dev/tools/build.mjs` then `node _dev/tools/audit.mjs`.
4. Preview at http://localhost:8765 (add `?v=2` etc. to bypass cache). Check desktop and a 375 px phone width.
5. Commit with a clear message. Ask the user before pushing.
6. After "push": `git push origin main`, then confirm on the live site, for example:
   `curl -s "https://alwaheedgroup.com/affiliated-groups/?t=$RANDOM" | grep -o 'company-card__name">[^<]*'`

## 7. Content model (`_dev/src/data.mjs`)

| Export | Used for |
| --- | --- |
| `site` | name, `url`, `launchReady`, phone, WhatsApp, emails, address, geo, hours, social links, `web3formsKey`, `storyVideoId` |

| `upcoming` | blurred "Coming Soon" cards with the rotating seal |
| `reasons, chairman, board, testimonials, homeFaqs, milestones, values, jobs, perks` | page sections |

### How to...
- **Add an affiliated group card:** put the logo in `_dev/assets/brand/partners/`, add a processing step in `images.py` (`GOLD_LOGOS` for gold artwork on dark badges, or a block in `other_logos()`), run it, add a `case` to `companyMark()` in `layout.mjs` with the real width and height, add the entry to `companies`. The grid is a centred flex wrap: 2 columns on phones, 4 from 700 px (`--cols` in `.company-grid`). Adjust columns so the last row looks balanced. Update the affiliated groups meta description if needed.
- **Add a project page:** add it to `projects` with images registered in `SOURCES` in `images.py`; it gets `/projects/<slug>/`, sitemap and schema automatically.
- **Launch an upcoming project:** move it from `upcoming` to `projects`.
- **Real teaser image for an upcoming project:** point its entry in `TEASERS` in `images.py` at the file; it is blurred automatically.

## 8. Design system

- **Fonts:** Cormorant Garamond (headings, serif) + Inter (body), from Google Fonts, loaded without blocking render. Self hosting was offered and not yet approved.
- **Colours** (`:root` in `main.css`): gold `#AA8844` (logo gold), gold deep `#8A6A2C` (small gold text, for contrast), gold light `#C9A961`, ink `#1C1915`, stone `#6B645A`, ivory `#FAF7F1`, sand `#EDE6D8`, espresso `#17130F` (dark sections). UPG documents use green `#22533A` with gold.
- **Logo:** Al Waheed emblem converted from the client PDF to SVG (`assets/img/brand/logo-*.svg`).
- **Components:** section heads with eyebrow, gold buttons, project cards with chips (`Booking from Rs. ...` highlighted), company cards, co-row profiles, person cards with matched portraits, doc cards, quote cards, stats, FAQ accordions, payment tables, unit tabs (ARIA tabs), lightbox (`<dialog>`), click to load Google Map and YouTube facades, mobile action bar (Call / WhatsApp / Enquire) and a floating WhatsApp button.
- **Animations** (`main.js`): IntersectionObserver reveals (`data-reveal`, `data-stagger`), counters, hero crossfade slider (slides 2 and 3 load after `load`), testimonial scroll track, rotating SVG seal on coming soon cards.
- **Images:** `pic(key, {...})` in `layout.mjs` outputs `<picture>` with AVIF and WebP `srcset`. Heroes have art directed portrait crops for phones (`-p` keys) with matching media specific preloads.
- **Leadership portraits:** `portraits.py` scales every face to the same size and eye line on one ivory backdrop with a gold ring; white backgrounds use a multiply blend, others a GrabCut cut out.

## 14. Gotchas

- **Dash guard source:** `build.mjs` checks `/[\u2013\u2014]/` written as escape sequences. Some editors and AI write tools convert the escapes into the real characters, which then makes the build fail on its own source. Keep them as escapes.
- **Windows:** set `PYTHONIOENCODING=utf-8` if Python prints fail with a cp1252 error. Run commands from the repository root. In Git Bash, complex heredocs with backticks or quotes break easily; write a small script file instead.
- **Caching while previewing:** add `?v=N` to the URL. Reveal animations and `content-visibility: auto` mean off screen sections may look empty in automated screenshots; scroll first or measure with JavaScript.
- **Payment tables on phones:** the tfoot uses a separate hidden middle cell; do not replace it with a colspan.
- **Company cards:** the grid uses flex with `height: auto` for equal height cards; the reveal script removes `data-reveal` after the transition so hover transforms work.
- **Logo keying:** gold badge logos (`GOLD_LOGOS`) need ring trim and bottom cut values per logo; colour logos on white or paper are handled in `other_logos()` (JRB keeps the white inside its badge).
- `images.py` deletes and rebuilds the generated image folders (`projects`, `united-palm-greens`, `khairunnisa-heights`, `soon`, `og`, `team`). Brand logos are overwritten in place; delete unused ones by hand.
- `sitemap.xml` `lastmod`, the careers JobPosting dates and the privacy policy date come from the build date (UTC), so they change on every build day.
